# Offline WebAuthn diagnostic

This local test harness uses the browser's real `navigator.credentials.create()` and `navigator.credentials.get()` APIs. It does not substitute a browser virtual authenticator, imitate Android signing, or manufacture successful authentication.

It is **not a production relying-party server or a login system**. Public test state and challenges exist only in page memory. Reloading loses that state. No private credential keys are stored or generated by the page.

## Run

From the repository root with the .NET 10 SDK:

```powershell
dotnet run --project tests/webauthn/server/KeyBridge.WebAuthn.Server.csproj -c Release -- tests/webauthn
```

If `dotnet` is installed outside PATH, invoke its full executable path. A convenience PowerShell wrapper is also available when your existing script-execution policy permits local scripts:

```powershell
./tests/webauthn/serve.ps1
```

Then manually open **http://localhost:8787** in a WebAuthn-capable browser. Use `localhost`, not an IP address or a file URL. Browsers normally treat localhost as a potentially trustworthy context without requiring a TLS certificate. If your policy blocks the API, the page reports that context failure.

The server uses .NET's `TcpListener` on **127.0.0.1:8787**. It needs no HTTP URL reservation, administrator rights, firewall changes, execution-policy bypass, Internet connection after SDK setup/build, or external JavaScript packages. It serves only six fixed routes, validates Host/Origin, closes each request, and supplies a restrictive Content Security Policy. URL paths never become filesystem paths. Press Ctrl+C to stop it. If the port is occupied, stop the process you intended to use there; the server does not kill other software or choose a different origin automatically. Use the direct .NET command when PowerShell blocks scripts; do not weaken policy for this fixture.

## Hardware prerequisites and manual procedure

1. Install Android KeyBridge, start its visible connection service, and connect the phone with a USB data cable.
2. Pair the Windows companion and phone by comparing both codes.
3. Start the USB/IP backend, attach using a verified compatible signed driver, and confirm the actual KeyBridge FIDO HID interface in Windows.
4. Open the diagnostic page and select **Register test credential**. Choose the USB security key in Windows. Inspect the localhost registration request and approve it yourself on Android.
5. The page validates the returned public-key registration. Next select **Authenticate & verify**, approve the authentication request yourself, and inspect the verification result.
6. Authenticate again to exercise counters. Disconnect the phone and start a new attempt; it must fail or be cancelled, never display signature success without a valid assertion.
7. Clear the page state when finished, then remove the `localhost` test credential from Android KeyBridge's vault. Clearing browser memory does not delete authenticator credentials.

The harness never launches a WebAuthn operation automatically. Cancel aborts a pending request; every attempt has a 90-second diagnostic deadline. Testing scripts below do not open a browser, invoke the Windows security dialog, perform pairing, or access a real authenticator.

## What is checked

Registration requests RP ID `localhost`, ES256, required user verification, cross-platform attachment, preferred discoverable storage, and `none` attestation. Authentication supplies the registered credential ID with the USB transport hint and requires user verification.

Both responses are checked for the expected operation type, unpredictable one-use challenge, exact browser origin, RP ID hash, credential identity, user presence, user verification, and valid flags. Registration parses bounded definite-length CBOR, the attested credential ID, and a public P-256 COSE key. Only an empty `none` attestation statement is supported. Assertion verification hashes the exact client-data bytes and uses WebCrypto to verify ES256 over `authenticatorData || SHA256(clientDataJSON)`, converting strict DER signatures into WebCrypto's fixed-width format. Returned user handles, when present, must match the test account. Nonzero signature counters must increase; authenticators consistently reporting zero are permitted by this policy.

`none` attestation contains no registration signature and proves no manufacturer, hardware security level, Android identity, or FIDO certification. Key possession is checked only by a successful subsequent assertion. The page cannot inspect the Windows driver or prove that the selected authenticator is KeyBridge. Confirm the phone prompt, companion activity, and device interface independently. A different real authenticator could also produce a valid ES256 result.

This test does not cover discoverable credential enumeration (authentication uses an allow list), attestation chains, ClientPIN, every extension, certification, persistence across page reloads, a remote relying party, or a production account recovery policy. Unsupported attestation formats or CBOR types are rejected explicitly.

## Automated helper checks

Node.js 22 or later runs the helper checks; the server smoke test also needs the .NET 10 SDK. No npm install is needed:

```powershell
node --test tests/webauthn/helpers.test.mjs
node tests/webauthn/server.test.mjs
```

The helper tests create ephemeral software test keys inside the Node test process to exercise validation and rejection paths. They are test fixtures, never part of Windows KeyBridge's authenticator path. The server test builds and starts this fixture's .NET server, sends HTTP probes, then terminates only that child process. It requires port 8787 to be free. Set `KEYBRIDGE_DOTNET` to the full .NET executable path if it is not on PATH.

Protocol references: [WebAuthn registration verification](https://www.w3.org/TR/webauthn-3/#sctn-registering-a-new-credential), [assertion verification](https://www.w3.org/TR/webauthn-3/#sctn-verifying-assertion), and [WebCrypto ECDSA](https://www.w3.org/TR/webcrypto/#ecdsa-operations).

Browser/phone/driver end-to-end behavior remains **not verified by the automated helper tests**.
